  <action>
    Add a new section to `app/routers/ui_api.py` (after the Products APIs section, before
    Broadcast APIs), following the exact auth-guard pattern already used by every endpoint in
    this file (`if not _is_authenticated(request): raise HTTPException(status_code=401)`):

    ```python
    @router.get("/api/alerts")
    async def api_alerts(request: Request):
        if not _is_authenticated(request):
            raise HTTPException(status_code=401)
        dead_events = query(
            "SELECT id, phone, payload, error, attempts, created_at FROM webhook_events "
            "WHERE processed = TRUE AND error LIKE %s ORDER BY created_at DESC LIMIT 100",
            ("dead-letter:%",),
        )
        failed_jobs = query(
            "SELECT id, kind, phone, payload, last_error, attempts, max_attempts, created_at "
            "FROM outbox_jobs WHERE status = 'failed' AND attempts >= max_attempts "
            "ORDER BY created_at DESC LIMIT 100",
        )
        for row in dead_events + failed_jobs:
            if row.get("created_at") and not isinstance(row["created_at"], str):
                row["created_at"] = row["created_at"].isoformat()
        return JSONResponse(content={"webhook_events": dead_events, "outbox_jobs": failed_jobs})


    @router.post("/api/alerts/webhook_events/{event_id}/retry")
    async def api_retry_webhook_event(event_id: str, request: Request):
        if not _is_authenticated(request):
            raise HTTPException(status_code=401)
        execute(
            "UPDATE webhook_events SET processed = FALSE, attempts = 0, error = NULL WHERE id = %s",
            (event_id,),
        )
        return {"ok": True}


    @router.post("/api/alerts/outbox_jobs/{job_id}/retry")
    async def api_retry_outbox_job(job_id: str, request: Request):
        if not _is_authenticated(request):
            raise HTTPException(status_code=401)
        execute(
            "UPDATE outbox_jobs SET status = 'pending', attempts = 0, last_error = NULL, "
            "updated_at = now() WHERE id = %s",
            (job_id,),
        )
        return {"ok": True}
    ```
    Both retry endpoints reset the existing row in place (not insert a new one) — this matches
    the mutation style already used throughout this codebase and preserves the row's
    `created_at`/history for audit purposes. Note for the SUMMARY: resetting
    `webhook_events.processed = FALSE` causes `handle_message()` to re-run from scratch on the
    next poll — the `wamid` unique constraint prevents the same inbound WhatsApp message from
    being inserted twice, but a retry can still re-run bot-command side effects if the original
    processing got partway through before failing (a real, narrow, pre-existing gap — not
    introduced by this plan, and out of scope to fully close per Phase 4's locked decisions).
  </action>
  <verify>Manual review — matches the exact auth-guard and query/execute usage pattern of every other endpoint in this file.</verify>
