<objective>
Swap the dashboard's authentication guard, atomically. Today three router files each hand-roll
`request.cookies.get("alyasmeen_session") == sha256(f"{SECRET_KEY}:{DASHBOARD_PASSWORD}")` —
one deterministic value, no identity, no expiry, no revocation. After this plan the same
cookie name carries an opaque per-operator session token resolved against `operator_sessions`,
and the login flow is email+password followed by TOTP.

This has to be one plan because the cookie's *meaning* changes: leaving any of the three guard
copies behind would lock the operator out of half the dashboard. The test suite is migrated in
the same plan for the same reason — three test files currently recompute the old token by hand.

Purpose: REQ-prod-auth-mfa + REQ-prod-session-opaque + REQ-dash-login.
Output: two new routers, a rewritten login page, an MFA challenge page, and a central test
auth fixture.
</objective>

  <name>Task 2: auth_routes.py — email+password login, TOTP challenge, logout</name>
  <files>app/routers/auth_routes.py, app/main.py, app/templates/login.html, app/templates/mfa_challenge.html</files>

    **Create `app/routers/auth_routes.py`** (plain `APIRouter(tags=["auth"])` — NO router-level
    guard; these routes must be reachable while signed out). Import `templates` from
    `app.routers.ui`, `app.services.auth as auth_service`, `app.services.sessions as sessions`,
    and the cookie/TTL constants from `app.shared.constants`.

    Routes:

    - `GET /login` — if `optional_operator(request)` resolves, 303 to `/orders`; else render
      `login.html` with `error=None`.

    - `POST /login` (Form: `email`, `password`):
      1. `result = auth_service.sign_in(email, password)`; on `AuthError`, re-render
         `login.html` with a generic Arabic error `"البريد الإلكتروني أو كلمة المرور غير صحيحة"`
         and status 401. Never reveal whether the email exists.
      2. If `result.mfa_required`: look up the device cookie —
         `device = sessions.find_trusted_device(result.user_id, request.cookies.get(DEVICE_COOKIE_NAME))`.
         - If `device` is not None -> the TOTP requirement is satisfied by remember-device;
           fall through to step 4 with `device_id=device["id"]`.
         - Else -> `token = sessions.create_pending_login(...)`, set
           `PENDING_LOGIN_COOKIE_NAME` (httponly, samesite=lax,
           `secure=not Config.USE_MOCK_WHATSAPP`, `max_age=PENDING_LOGIN_TTL_MINUTES*60`) on a
           `TemplateResponse` for `mfa_challenge.html`, and RETURN. **Do not mint a dashboard
           session on this path.** This is the check that stops MFA from being decorative — a
           successful `sign_in_with_password` only reaches AAL1 even when TOTP is enrolled.
      3. If `not result.mfa_required` (no verified factor enrolled yet): allow the login and
         set a template flag so the dashboard can nag for enrollment. CONTEXT locks enrollment
         as *assisted, not a forced self-serve wall*, so a not-yet-enrolled operator must still
         be able to sign in — otherwise the first login is impossible. Write an
         `audit`-less structlog warning `login_without_mfa` with the email.
      4. Mint the session: `raw = sessions.create_session(result.user_id, result.email,
         result.is_admin, device_id, request.headers.get("user-agent"))`, 303 to `/orders`,
         `resp.set_cookie(SESSION_COOKIE_NAME, raw, httponly=True, samesite="lax",
         secure=not Config.USE_MOCK_WHATSAPP, max_age=SESSION_TTL_DAYS*86400)`, and delete the
         pending cookie.

    - `POST /login/mfa` (Form: `code`): read `PENDING_LOGIN_COOKIE_NAME`; `pending =
      sessions.consume_pending_login(token)`; if None -> 303 to `/login` (expired/replayed).
      `auth_service.verify_totp(pending["access_token"], pending["refresh_token"],
      pending["factor_id"], code)`; on `AuthError` re-render `mfa_challenge.html` with
      `"الرمز غير صحيح، جرّبي مرة أخرى"` at status 401 **and re-issue a fresh pending_login row
      + cookie** so she gets another attempt without re-entering her password. On success:
      mint/refresh the device token (`sessions.mint_token()` if the device cookie is absent),
      `device_id, created = sessions.remember_device(user_id, device_token,
      label=request.headers.get("user-agent"))`, mint the opaque session as in step 4, set BOTH
      the session cookie and the device cookie (`max_age=DEVICE_COOKIE_TTL_DAYS*86400`), delete
      the pending cookie, 303 to `/orders`. Stash `created` on `request.state.new_device` and
      leave a `# 05-09 fires the admin WhatsApp alert here` comment — plan 05-09 wires it.

    - `GET /logout` — revoke only THIS session (`sessions.revoke_session(op.session_id)` via
      `optional_operator`), delete the session cookie, keep the device cookie (multi-device is
      locked in CONTEXT: logging out on the laptop must not sign out the phone), 303 to
      `/login`.

    - `POST /logout-all` — requires `Depends(require_operator)`;
      `sessions.revoke_all_for_user(op.user_id)`; delete the session cookie; 303 to `/login`.

    Register the router in `app/main.py` with `app.include_router(auth_router)` placed
    immediately before `app.include_router(ui_router)`.

    **`app/templates/login.html`** — rewrite the form from a single password field to `email` +
    `password` (both `required`, email `type="email"`, `autocomplete="username"` /
    `"current-password"`). Keep the existing premium design system exactly: Cairo font,
    `#006948` green, page background `#f0f7f4`, 20px card radius, `#e8f3ee` border, Material
    Symbols icons, `dir="rtl"`, Arabic copy. Add a "نسيت كلمة المرور؟" link to
    `/login/reset-request` (plan 05-09 builds the route; a 404 until then is acceptable and must
    be noted in the SUMMARY).

    **`app/templates/mfa_challenge.html`** — NEW. Same design system, RTL. One centred card:
    heading `"رمز التحقق"`, help text `"أدخلي الرمز المكوّن من ٦ أرقام من تطبيق المصادقة"`, a
    single `<input name="code" inputmode="numeric" pattern="[0-9]{6}" maxlength="6" autofocus>`
    styled large and letter-spaced, a full-width `#006948` submit button `"تأكيد"`, the `error`
    block when present, and a small "الرجوع لتسجيل الدخول" link to `/login`. Form posts to
    `/login/mfa`. No Alpine, no fetch — a plain form POST, exactly like the current login page.
