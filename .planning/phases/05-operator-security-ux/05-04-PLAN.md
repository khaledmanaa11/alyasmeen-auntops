<objective>
Close the two remaining Phase 5 security gaps that are pure middleware: CSRF protection on
every mutating dashboard route, and a security-header set on every response.

Every dashboard mutation today is a cookie-authenticated `fetch()` POST with no CSRF token —
forgeable from any page that can get the operator's browser to issue a request. Rather than
editing nine `fetch()` call sites, this plan adds a double-submit cookie via `starlette-csrf`
plus one shared script that wraps `window.fetch`, so the call sites stay untouched.

This plan runs alone in its wave, immediately after the auth swap and before any new template
is built, so that `handoffs.html`, `audit.html`, `account.html` and the reworked `alerts.html`
are all born with CSRF wiring already in place. Since it is the one wave that touches every
template anyway, it also extracts the six-times-duplicated nav block into a single
`_nav.html` partial — otherwise plans 05-07, 05-08 and 05-09 would each have to edit the same
six files and could not run in parallel.

Purpose: REQ-prod-csrf + REQ-prod-sec-headers (success criterion 3).
Output: one new dependency, one middleware module, one static script, header coverage on every
response.
</objective>

    **`app/main.py`:** after the routers are included, add
    ```python
    from starlette_csrf import CSRFMiddleware
    from app.shared.constants import SESSION_COOKIE_NAME

    app.add_middleware(
        CSRFMiddleware,
        secret=Config.SECRET_KEY,
        cookie_name="csrftoken",
        header_name="x-csrftoken",
        cookie_secure=not Config.USE_MOCK_WHATSAPP,
        cookie_samesite="lax",
        sensitive_cookies={SESSION_COOKIE_NAME},
    )
    ```
    Add a comment explaining `sensitive_cookies`: enforcement only engages for requests that
    actually carry the dashboard session cookie, so `POST /whatsapp/webhook` (authenticated by
    Meta's `X-Hub-Signature-256` over the raw body, never by a browser cookie) and the dev-only
    `/dev/*` routes are exempt **by construction**, with no `exempt_urls` regex to maintain

    unaffected for the same reason — no session cookie exists yet at that point.

    Middleware ordering note to include as a comment: Starlette applies `add_middleware` in
    reverse registration order, so register CSRF here and `SecurityHeadersMiddleware` (Task 2)
    after it, which puts the headers middleware outermost — a CSRF 403 response then still
    carries the security headers.

    **`app/static/js/csrf.js`** — NEW (the `app/static` mount already exists in `main.py`):
    ```js
    (function () {
      const orig = window.fetch;
      function readCookie(name) {
        const m = document.cookie.match('(?:^|; )' + name + '=([^;]*)');
        return m ? decodeURIComponent(m[1]) : null;
      }
      window.fetch = function (input, init) {
        init = init || {};
        const method = (init.method || 'GET').toUpperCase();
        if (['POST', 'PUT', 'PATCH', 'DELETE'].indexOf(method) !== -1) {
          init.headers = Object.assign({}, init.headers || {}, {
            'x-csrftoken': readCookie('csrftoken') || ''
          });
        }
        return orig(input, init);
      };
    })();
    ```
    Add a header comment: this exists so the nine existing `fetch()` call sites across
    `orders.html`, `products.html`, `broadcast.html` and `alerts.html` need zero changes, and
    so every future call site is covered automatically.

<task type="auto">
  <name>Task 2: SecurityHeadersMiddleware</name>
  <files>app/middleware/__init__.py, app/middleware/security_headers.py, app/main.py</files>
  <action>
    Create the `app/middleware/` package (`__init__.py` empty) and
    `app/middleware/security_headers.py` with a `SecurityHeadersMiddleware(BaseHTTPMiddleware)`
    whose `dispatch` generates `nonce = secrets.token_urlsafe(16)`, assigns
    `request.state.csp_nonce = nonce`, awaits `call_next`, and then sets:

    - `Content-Security-Policy`:
      `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://cdn.tailwindcss.com https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'; upgrade-insecure-requests`
    - `X-Content-Type-Options: nosniff`
    - `X-Frame-Options: DENY`
    - `Referrer-Policy: strict-origin-when-cross-origin`
    - `Permissions-Policy: geolocation=(), microphone=(), camera=()`
    - `Strict-Transport-Security: max-age=15552000; includeSubDomains` — ONLY when
      `not Config.USE_MOCK_WHATSAPP` (never send HSTS from a local http dev server).

    Two comments are mandatory in the file, because both look like mistakes otherwise:
    1. `'unsafe-inline'` + `'unsafe-eval'` are deliberate. The dashboard loads Tailwind via the
       Play CDN, which injects unnonced `<style>` tags at runtime, and Alpine.js core evaluates
       `x-data`/`x-on` expressions through `new Function()`. A nonce-only, no-unsafe policy
       silently breaks the entire dashboard (Tailwind classes stop applying, Alpine throws
       "Refused to evaluate a string as JavaScript"). Tightening this requires precompiling
       Tailwind and switching to Alpine's CSP build — a frontend-build migration that is
       explicitly out of this phase's scope. Record it as a follow-up in the SUMMARY.
    2. The nonce is generated and exposed on `request.state` but is intentionally not yet
       required by the policy, so a future strict CSP is a config change rather than a
       re-plumb.

    Do NOT add `HTTPSRedirectMiddleware` and do NOT branch on `request.url.scheme`: the Procfile
    runs uvicorn without `--proxy-headers`, so behind Railway's TLS-terminating edge the scheme
    reads `http` and a redirect middleware would loop forever. Setting the HSTS *header* with no
    redirect sidesteps this entirely.

    Register in `app/main.py` with `app.add_middleware(SecurityHeadersMiddleware)` placed
    AFTER the `CSRFMiddleware` registration (see the ordering note in Task 1).
  </action>

Kill the server.</verify>
