<objective>
Build the app-owned opaque session store that becomes the single source of truth for "is this
dashboard operator currently logged in" — three new tables plus a `sessions.py` service that
does all of the session lifecycle work the locked CONTEXT decisions require (30-day fixed
expiry, multi-device, logout-everywhere, revoke-on-credential-change, admin session listing,
30-day remember-this-device for MFA).

This plan touches NO routes and NO templates. It is pure data + service layer so it can run in
parallel with plan 05-02 (the Supabase Auth wrapper). Plan 05-03 wires the two together.

Purpose: REQ-prod-session-opaque — the dashboard must stop trusting a deterministic
`SHA-256(SECRET_KEY:DASHBOARD_PASSWORD)` cookie value that can never expire or be revoked.
Output: one migration, one shared-constants addition, `app/services/sessions.py`, unit tests.
</objective>

<task type="auto">
  <name>Task 2: Migration for operator_sessions, trusted_devices, pending_logins</name>
  <files>supabase/migrations/20260828000000_operator_auth.sql</files>
  <action>
    Create the migration. Follow the style of `20260614000001_durable_messaging.sql` (UUID PKs
    via `gen_random_uuid()`, `TIMESTAMPTZ DEFAULT NOW()`, `CREATE TABLE IF NOT EXISTS`) and
    the RLS pattern of `20260614000003_security_rls.sql` (enable RLS + a single
    `FOR ALL TO service_role USING (true) WITH CHECK (true)` policy per table — the app only
    ever reaches these tables through the service_role-keyed `database.py` client).

    Do NOT name any table `sessions` — that name is already taken by the WhatsApp cart-state
    table and colliding would break the bot.

    ```sql
    CREATE TABLE IF NOT EXISTS operator_sessions (
      id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      user_id      UUID NOT NULL,               -- Supabase auth.users.id
      email        TEXT NOT NULL,               -- denormalized for the admin session list
      is_admin     BOOLEAN NOT NULL DEFAULT FALSE,
      token_hash   TEXT NOT NULL UNIQUE,        -- sha256(raw token); raw token lives only in the cookie
      device_id    UUID,                        -- FK-by-convention to trusted_devices.id (nullable)
      user_agent   TEXT,
      created_at   TIMESTAMPTZ DEFAULT NOW(),
      last_seen_at TIMESTAMPTZ DEFAULT NOW(),
      expires_at   TIMESTAMPTZ NOT NULL,
      revoked_at   TIMESTAMPTZ
    );
    CREATE INDEX IF NOT EXISTS idx_operator_sessions_user ON operator_sessions(user_id, revoked_at);

    CREATE TABLE IF NOT EXISTS trusted_devices (
      id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      user_id            UUID NOT NULL,
      device_token_hash  TEXT NOT NULL,
      label              TEXT,                  -- trimmed user-agent, for the admin session list
      mfa_verified_until TIMESTAMPTZ,
      created_at         TIMESTAMPTZ DEFAULT NOW(),
      last_seen_at       TIMESTAMPTZ DEFAULT NOW(),
      UNIQUE (user_id, device_token_hash)
    );

    CREATE TABLE IF NOT EXISTS pending_logins (
      id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      token_hash    TEXT NOT NULL UNIQUE,
      user_id       UUID NOT NULL,
      email         TEXT NOT NULL,
      is_admin      BOOLEAN NOT NULL DEFAULT FALSE,
      factor_id     TEXT NOT NULL,
      access_token  TEXT NOT NULL,   -- AAL1 Supabase tokens, needed to run challenge_and_verify
      refresh_token TEXT NOT NULL,
      created_at    TIMESTAMPTZ DEFAULT NOW(),
      expires_at    TIMESTAMPTZ NOT NULL
    );
    ```

    `pending_logins` exists so the AAL1 Supabase tokens never round-trip through the browser
    between the password step and the TOTP step. Rows are single-use and short-lived (5 min);
    add a trailing comment saying so.

    Then enable RLS + add the three service_role policies, and finish with a
    `COMMENT ON TABLE` for each explaining its role.

    Do NOT apply the migration to the live project in this plan (Phase 4's live-rollout plan
    owns that ritual and the live push happens once at the end of the phase, in 05-09).
  </action>

    Public surface (exact names — plans 05-03/05-05/05-06 import these):

    ```python
    @dataclass(frozen=True)
    class Operator:
        user_id: str
        email: str
        is_admin: bool
        session_id: str

    def mint_token() -> str                     # secrets.token_urlsafe(OPAQUE_TOKEN_BYTES)
    def _hash(raw: str) -> str                  # sha256 hexdigest

    def create_session(user_id, email, is_admin, device_id=None, user_agent=None) -> str
        # INSERT ... expires_at = now() + interval '30 days' (use SESSION_TTL_DAYS in the
        # interval string built from the constant, not a hardcoded literal). Returns raw token.

    def lookup_session(raw_token: str) -> Operator | None
        # SELECT id, user_id, email, is_admin FROM operator_sessions
        # WHERE token_hash = %s AND revoked_at IS NULL AND expires_at > now()
        # On hit, best-effort UPDATE last_seen_at = now() (wrap in try/except: a failed
        # last_seen_at write must never log the operator out). Return None on miss/empty token.

    def revoke_session(session_id: str) -> None
    def revoke_all_for_user(user_id: str, except_session_id: str | None = None) -> None
        # UPDATE ... SET revoked_at = now() WHERE user_id = %s AND revoked_at IS NULL
        # [AND id <> %s]. This is the one statement behind BOTH "log out everywhere" and
        # "any credential change revokes all sessions".
    def list_sessions_for_user(user_id: str) -> list[dict]
        # active only, newest first; returns id, email, user_agent, created_at, last_seen_at,
        # expires_at — never token_hash.
    def list_active_sessions() -> list[dict]    # every operator; powers the admin session view

    def find_trusted_device(user_id: str, raw_device_token: str | None) -> dict | None
        # returns the row only when mfa_verified_until > now(); None otherwise.
    def remember_device(user_id: str, raw_device_token: str, label: str | None = None) -> tuple[str, bool]
        # upsert on (user_id, device_token_hash); sets mfa_verified_until = now() + 30 days and
        # last_seen_at = now(). Returns (device_id, created) where created=True ONLY on insert —
        # 05-05 uses that flag to fire the new-device WhatsApp alert to the admin.

    def create_pending_login(user_id, email, is_admin, factor_id, access_token, refresh_token) -> str
    def consume_pending_login(raw_token: str) -> dict | None
        # SELECT the unexpired row by token_hash, DELETE it, return it. Single use.
    def purge_expired() -> None                 # housekeeping; DELETE expired pending_logins
    ```
