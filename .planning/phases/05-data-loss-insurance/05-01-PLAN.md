# Plan: Phase 5 — Data-Loss Insurance

Insure against data loss on the free tier with an automated nightly export and a restore that has actually been proven, not assumed.

## Goal
- Automated nightly export of critical Supabase tables (BAK-01).
- Documented and tested restore runbook (BAK-02).

## Requirements
- **BAK-01**: A nightly automated export of critical tables runs to durable storage (free-tier insurance).
- **BAK-02**: A tested restore runbook exists — recovery from the export is proven, not assumed.

## Strategy
1. **Automated Export**:
   - Create `app/services/backup.py` to handle the export using `npx supabase db dump`.
   - Use `AsyncIOScheduler` in `app/main.py` to run the job nightly (e.g., at 03:00 UTC).
   - Exports will be saved to a local `backups/` directory (added to `.gitignore`).
   - *Note*: Ideally, these should be moved to off-site storage (S3), but for M1, establishing the automated export locally is the baseline.
2. **Restore Runbook**:
   - Create `docs/RESTORE.md` with step-by-step instructions for recovery.
3. **Validation**:
   - Manually trigger the backup job and verify the `.sql` file is created and contains data.
   - Perform a "restore drill" against a local or test database to verify BAK-02.

## Proposed Changes

### 1. New Service: `app/services/backup.py`
- Function `run_backup()`:
  - Calls `npx supabase db dump --linked --data-only`.
  - Saves to `backups/backup_YYYY-MM-DD_HHMM.sql`.
  - Implements basic retention (keep last 7 days).

### 2. Update `app/main.py`
- Import `run_backup` and add to scheduler.

### 3. Documentation
- Create `docs/RESTORE.md`.

### 4. Git Ignore
- Add `backups/` to `.gitignore`.

## Verification Plan

### Automated Tests
- Create `tests/unit/test_backup.py` to verify:
  - The backup command is constructed correctly.
  - The retention logic works (deletes old files).

### Manual Drill
1. Run `python -m app.services.backup` (or similar trigger).
2. Verify `backups/*.sql` exists.
3. Follow `docs/RESTORE.md` to verify the backup can be applied.
