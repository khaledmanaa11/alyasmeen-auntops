<objective>
Close the loop: put the deterministic gate in front of every AI tool call (success criterion
1), let Claude escalate for real, and make an AI outage produce a human follow-up instead of
a silent apology.

`_make_tool_executor`'s closure (`app/services/processor.py:393-411`) is the single
chokepoint every AI tool call already passes through — and today it has no validation layer
whatsoever. It dispatches Claude's raw arguments straight into `_tool_add_to_cart`,
`_tool_show_menu`, `_tool_get_order_status`, `_tool_save_address`. This plan wraps that
dispatch, adds the fifth tool's implementation, and consumes 03-03's new
`AIUnavailableError`.

Output: a fully policy-gated tool path, a working `request_human_handoff`, and AI-failure
escalation — the last three of the five handoff triggers this phase owes.
</objective>

**(b) Rewrite the executor closure** in `_make_tool_executor(phone, st, cart)`:

```python
def executor(name: str, args: dict) -> str:
    log.info("tool_call", name=name, args=args, phone=phone)

    decision = policy.validate(name, args, {
        "phone": phone,
        "paused": bool(st.get("paused")),
        "cart": cart,
        "catalog": catalog(),
        # Called by policy ONLY for order-scoped tools — none exist today, so
        # the gate costs zero extra database reads on the hot path.
        "order_status_provider": lambda: (get_latest_order(phone) or {}).get("status"),
    })

    if not decision.allowed:
        log.warning("tool_denied", name=name, code=decision.code, phone=phone)
        if decision.escalate and _open_handoff(
            phone, "policy_denied", {"tool": name, "code": decision.code}
        ):
            st["handoff_pending"] = True
        return decision.message

    args = decision.args
    ...dispatch as before, using the normalised args...
```

Details that matter:
- `catalog()` is already imported in `processor.py` and is patched by every existing test
  (`tests/unit/test_processor.py`'s autouse `_catalog` fixture patches `processor.catalog`)
  — passing it in from here is exactly why `policy.py` was kept I/O-free.
- `order_status_provider` is a **lambda, not a value**: policy only invokes it for
  order-scoped tools, so `get_latest_order()` never runs for today's five tools. Do not
  eagerly evaluate it; that would add a database round-trip to every single tool call inside
  the worker's `BlockingScheduler` loop (Pitfall 3).
- On denial, return `decision.message` as the tool result. `ai_service.py`'s agentic loop
  feeds that string back to Claude, which then writes a normal conversational reply around
  it — the customer sees a natural sentence, not an error code.
- `st["handoff_pending"]` is consumed in task 2. Only set it when the handoff actually
  opened.
- Keep the `return f"Tool {name} not found"` fallthrough as dead-code defence, but note that
  policy's `unknown_tool` rule now catches this first.

**(c) Dispatch with normalised args.** `add_to_cart` now receives the canonical catalog name
and the clamped integer from `decision.args`; `show_menu` the truncated category;
`save_address` the stripped address.

```python
def _tool_request_human_handoff(phone: str, st: dict, reason: str) -> str:
    """Claude's escalation tool. Opens a REAL handoff — the whole point is that
    'I've passed this to Hanan' is backed by a database row, not by prose."""
    if _open_handoff(phone, "ai_requested", {"reason": reason[:200]}):
        st["handoff_pending"] = True
        return "تم تحويل المحادثة لحنان بنجاح."
    return "تعذّر التحويل حالياً — اعتذري للزبونة واطلبي منها المحاولة بعد قليل."
```

On failure it must NOT set `handoff_pending`: if the durable write did not happen, the
customer must not be told it did. Add the dispatch branch in the executor:
`if name == "request_human_handoff": return _tool_request_human_handoff(phone, st, args.get("reason", ""))`.

**(b) Consume the flag in `handle_message`**, immediately after the `generate_reply` call
returns and **before** `append_history(phone, "assistant", reply)` / `queue_text`:

```python
if st.pop("handoff_pending", False):
    # Replace the model's reply with the deterministic acknowledgement. The
    # customer gets exactly ONE message, and its wording is ours: a handoff
    # acknowledgement must match what actually happened in the database.
    reply = HANDOFF_ACK_REPLY
```

This is why the tool does not queue its own message. Queuing inside the tool would send the
acknowledgement *and* Claude's second-call reply — two messages for one event, with the
model's version free to over-promise ("حنان رح تتصل فيكِ خلال ساعة"). Using `st.pop` also
keeps the transient flag out of anything `save_session` might later persist.

`HANDOFF_ACK_REPLY` already exists from plan 03-04 — reuse it, do not define a second
string.

**(c) Ordering note.** The session is now paused, so `save_session(phone, st)` at the end of
`handle_message` runs as normal — and must not clear the pause. 03-04 already made
`save_session`'s SQL (and the FakeDB mirror) preserve `paused`; add a brief comment at this
call site pointing at that guarantee, since it is non-obvious and a regression here would
silently un-mute the bot on the very next message.

try:

its own failures (03-04), so a handoff problem on top of an AI problem still cannot cost her
the message.
