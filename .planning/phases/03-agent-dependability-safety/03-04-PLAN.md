<objective>
Wire the two deterministic handoff triggers that do not need the AI, and close the two
confirmed live gaps behind them:

- **Gap 1 — `sessions.paused` is never read.** `load_session()`
  (`app/routers/whatsapp_helpers.py:54-68`) does not even `SELECT` the column, and no code
  path anywhere in the message pipeline consults it. Phase 5 shipped a whole handoffs UI
  with a "أعد للبوت" button on the premise that pausing stops the bot. It does not. Today
  the bot would happily keep answering a customer the aunt has taken over.
- **Gap 2 — non-text messages vanish.** `process_event`
  (`app/services/processor.py:198-238`) branches on `text` and `interactive` and has no
  `else`. A voice note, photo, sticker, or document is marked `processed = TRUE` with no
  reply, no log, and no handoff. The customer is simply ignored. The eval dataset has three
  such cases (ids 47, 67, and the image-reference case) precisely because it is a common
  real-world input for this shop.

Output: the paused gate, keyword-triggered handoff, media-triggered handoff, and the
conftest extension that makes all of it testable without touching production.
</objective>

**(a) `handle_unsupported_media(phone, msg_type, name="")`** in `processor.py`, next to

MEDIA_TYPE_LABELS = {
    "audio": "صوتية", "voice": "صوتية", "image": "صورة", "sticker": "ملصق",
    "document": "ملف", "video": "فيديو", "location": "موقع", "contacts": "جهة اتصال",

Body, in this order:
1. `upsert_customer(phone, name)` — **mandatory and easy to miss.** `handoffs.phone` carries
   a live FK to `customers(phone)`
   (`supabase/migrations/20260614000001_durable_messaging.sql:48`), and unlike
   `handle_message` this path has not already upserted the customer. A brand-new customer
   whose very first message is a voice note would otherwise blow up on the FK.
2. `append_history(phone, "user", f"[رسالة {label}]")` where `label` comes from
   `MEDIA_TYPE_LABELS.get(msg_type, msg_type)` — mirrors how the dataset itself represents
   these inputs (`[رسالة صوتية - 0:43]`, `[ملصق]`) and gives the aunt something to see in the
   transcript.
3. `queue_text(phone, UNSUPPORTED_MEDIA_REPLY)` and
   `append_history(phone, "assistant", UNSUPPORTED_MEDIA_REPLY)`.
4. `_open_handoff(phone, "unsupported_media", {"msg_type": msg_type})`.
5. `log.info("unsupported_media", phone=phone, msg_type=msg_type)`.

Order matters: the customer-facing reply is queued before the handoff so a handoff failure
cannot cost her the reply.

**(b) Wire it into `process_event`** (`processor.py:214-223`). After the `text` and
`interactive` branches, add:

```python
else:
    handle_unsupported_media(phone, msg_type or "unknown", name)
```

Two details:
- Guard against re-entry when the customer is already paused: `handle_unsupported_media`
  should check `load_session(phone).get("paused")` first and, if paused, only
  `append_history` the placeholder and return — same rule as the text path. Otherwise every
  voice note during an active handoff re-sends the same apology.
- The `text` branch currently does nothing when `body` is empty
  (`if text:` at line 216). Leave that as-is — an empty text body is a malformed payload, not
  an unsupported media type — but add a `log.info("empty_text_message", ...)` in an `else`
  so it stops being invisible.
- Do **not** touch `app/routers/whatsapp.py`. It is a webhook receiver that persists to
  `webhook_events` and computes no replies; all bot logic belongs here.
