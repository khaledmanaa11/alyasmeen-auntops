# Plan: Phase 6 — Bounded Growth (Retention)

Keep the two unbounded tables from growing forever by running retention jobs that prune old rows safely.

## Goal
- Automatically prune old `chat_history` rows (RET-01).
- Automatically prune resolved/old `retry_queue` rows (RET-02).
- Ensure retention windows are configurable (Success Criterion 3).

## Requirements
- **RET-01**: A retention job prunes old `chat_history` rows.
- **RET-02**: A retention job prunes resolved/old `retry_queue` rows.

## Strategy
1. **Configuration**:
   - Add `retention` section to `config/setup.json` with `chat_history_days` and `retry_queue_days`.
2. **Implementation**:
   - Create `app/services/retention.py` to handle the pruning logic using SQL `DELETE` commands.
   - Use `AsyncIOScheduler` in `app/main.py` to run the job daily (e.g., at 04:00 UTC).
3. **Verification**:
   - Create unit tests in `tests/unit/test_retention.py` to verify the SQL commands and retention logic.
   - Manually trigger the retention job and verify rows are deleted.

## Proposed Changes

### 1. Configuration: `config/setup.json`
- Add `retention` block:
  ```json
  "retention": {
    "chat_history_days": 30,
    "retry_queue_days": 30
  }
  ```

### 2. New Service: `app/services/retention.py`
- Function `run_retention()`:
  - Reads windows from `Config.APP_CONFIG`.
  - Executes `DELETE FROM chat_history WHERE created_at < now() - INTERVAL 'X days'`.
  - Executes `DELETE FROM retry_queue WHERE resolved = TRUE AND created_at < now() - INTERVAL 'Y days'`.

### 3. Update `app/main.py`
- Import `run_retention` and add to scheduler.

## Verification Plan

### Automated Tests
- Create `tests/unit/test_retention.py` to verify:
  - The retention job correctly calls `execute` with the right SQL.

### Manual Drill
1. Insert "old" dummy data into `chat_history` and `retry_queue` (resolved).
2. Run `python -m app.services.retention`.
3. Verify the old rows are gone and new/unresolved rows remain.
