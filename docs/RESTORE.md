# Restore Runbook: ALYASMEEN AuntOps

This document describes how to restore the Supabase database from the automated exports generated by `app/services/backup.py`.

## Overview
- **Backup Location**: `backups/backup_YYYY-MM-DD_HHMM.sql` (on the application server).
- **Format**: Data-only SQL dump (`INSERT` statements).
- **Frequency**: Daily at 03:00 UTC.
- **Retention**: Last 7 backups.

## Prerequisites
1. **Supabase CLI**: Installed and linked to the project (`npx supabase login`, `npx supabase link`).
2. **Database Password**: The `SUPABASE_DB_PASSWORD` used for the project.
3. **Fresh/Existing Project**: A Supabase project with the schema already applied (via `npx supabase db push` or manual migration).

## Restore Procedure

### Step 1: Identify the Backup
Locate the desired backup file in the `backups/` directory on the server.
```bash
ls -lh backups/
```

### Step 2: Prepare the Target Database
If you are restoring to a fresh project, ensure all migrations have been applied so the tables exist.
```bash
npx supabase db push
```

### Step 3: Apply the Data Export
Use `psql` or the Supabase CLI to apply the SQL file. The Supabase CLI's `db dump` output is designed to be applied via `psql` to the remote database.

Since we are on the free tier without direct DB access in some environments, you can use the Supabase SQL Editor or `psql` if you have the connection string.

**Option A: Using psql (Recommended)**
Get your connection string from Supabase Dashboard -> Project Settings -> Database.
```bash
psql "postgresql://postgres:[YOUR_PASSWORD]@db.[YOUR_PROJECT_REF].supabase.co:5432/postgres" -f backups/backup_YYYY-MM-DD_HHMM.sql
```

**Option B: Using Supabase CLI (Local Dev)**
If you are restoring to a local Supabase instance for testing:
```bash
npx supabase db reset # Warning: wipes local data
psql -h localhost -p 54322 -U postgres -d postgres -f backups/backup_YYYY-MM-DD_HHMM.sql
```

## Verification
After restoration, verify the data:
1. Check the `orders` table count: `SELECT COUNT(*) FROM orders;`
2. Check the `customers` table: `SELECT COUNT(*) FROM customers;`
3. Verify the latest orders match the expected state before the backup.

## Disaster Recovery Drill (Quarterly)
To ensure this runbook remains valid, perform a restore drill every 3 months:
1. Create a new temporary Supabase project.
2. Apply migrations.
3. Restore the latest backup.
4. Verify application functionality against the temporary project.
